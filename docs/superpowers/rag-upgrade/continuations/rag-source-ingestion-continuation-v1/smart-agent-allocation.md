Routine independent review may use Sol High where the actual diff and formal floor allow it. Sensitive schema/privacy/clinical/concurrency/retrieval review uses Astra High or xhigh as required. Reviewer role and model are separate dimensions; selecting a cheaper role name does not change intrinsic risk. No unknown unit receives a default permissive route. Higher-effort architecture/SQL/lease decisions retain their applicable floor even inside a High implementation task.

Use controller + at most two children by default. While one writer works, one read-only scout may prepare the next unit from frozen accepted source/hash inputs. After the writer freezes the complete range, two reviewers may inspect independent specialties, followed by later waves until every mandatory specialty is covered. A third child slot requires a concrete independent use and controller release; do not treat available capacity as reserved capacity. No recursive spawning, no overlapping writers, no review of moving files and no bypass of coordinator leases.

One designated gate owner runs each check; all reviewers use the same command/result/head/dependency package. They may request a missing discriminating check but do not each repeat the same suite. All final task/tranche/continuation reviews still judge the complete corrected original range; unchanged evidence reuse cannot turn this into correction-only review.

New units use fresh implementers. Correction rounds 1–3 use the same suitable writer with exact findings, current diff and failure history. Diagnose missing context, broken commands, dependencies and contention before attributing failure to model capability. Repair context first; repeated substantive failures in rounds 4–5 justify controlled fresh escalation. At round 6 stop automatic redispatch and have the controller resolve cause/scope/decision; it does not waive unresolved Critical/Important findings. Stale/unavailable writer context is an explicit reason for replacement, not automatic churn.

Every future brief records unit, immutable original base, current allowed paths, boundaries, frozen source inputs, risk/floor, planned route, exact checks and stop conditions. Every report records returned agent identity and actual route only when exposed by execution telemetry. A tool accepting a requested route is not proof it ran; unavailable model/effort evidence stays unavailable and blocks a formal route claim. No invented tool parameters, recursive agents, provider access or implicit task messages.

Compatibility is deliberately limited. The parent P-phase checker does not currently establish U/C phase acceptance or this new allocation. Use a reviewed manual continuation record and the existing canonical full-range review-package writer, preserving old hashes. Do not mutate `programme-manifest.json`, inject unknown receipt fields, invoke `--accept-phase C01`/`--resume U03`, lower floors or copy the other RAG worktree's helper. Any requested automation extension needs a separate small implementation/verification task. The execution environment and evidence compatibility must be checked before any authorised first use.
