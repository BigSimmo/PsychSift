## Supported scope

Current upload admission permits PDF, DOCX, XLSX and TXT (src/lib/http.ts:78). Approved-source acquisition also supports its governed HTML/PDF route. Repository-owned content uses approved static/registry producers. This matrix does not add PPTX, arbitrary image uploads, legacy Office macros, encrypted-document decryption, executable spreadsheets, general web crawling or new source licences.

DOCX needs native paragraph/table/media anchors; XLSX needs worksheet/cell/range anchors. Do not label those as physical PDF pages. Unsupported embedded features must have explicit limitations rather than silently promising extraction.

Use synthetic, repository-owned or explicitly permitted fixtures. No patient information, live URLs, provider calls or external references should be resolved by the offline suite. Expected evidence must be authored independently of the extractor implementation.

## Acceptance metrics

For this finite matrix, require:

1. **100% of nominated critical evidence atoms and relationships preserved on positive supported fixtures; negative/incomplete variants withheld with their expected reason.** Report preserved, withheld and missing counts separately against independently authored source expectations. Withholding a supported positive fixture cannot pass. “Withheld” does not count as successful extraction or eligibility.
2. **Zero unsupported critical relationships marked supported**, including dose, unit, polarity, population, recommendation strength and table alignment mutations.
3. **Every exposed anchor resolves** against the correct persisted version and coordinate system. Unresolvable or approximate anchors are marked as such and cannot masquerade as exact.
4. **Zero silent limit losses.** Expected counts, actual counts and reasons reconcile.
5. **Zero stale writes or scope violations** in the selected executable concurrency/permission schedules once those tests are authorised.
6. **Zero false corroboration** from original/derivative pairs in the selected lineage cases.
7. **No automatic inheritance of the U02 offline exception.** New failures are classified at the changed unit's exact code/dependency boundary.

Do not collapse these into one weighted quality percentage that allows a severe missing contraindication to be offset by many correct paragraphs. Keep failures and coverage denominators visible.

## Smallest credible execution tiers

- During implementation: one failing producer/adapter regression, then the affected focused selector.
- Extraction proof: existing local extractors using synthetic fixture bytes and permitted temporary outputs, only after implementation/testing authority.
- Persistence/permissions/concurrency: separately authorised disposable local database with actual SQL and controlled interleavings. Mock RPC argument tests are necessary but insufficient.
- Provider parity: separately authorised, bounded comparison after local evidence is sound; count calls/cost and preserve failed cases.
- Hosted/clinical/Answer: separately authorised exact-deployment and source-governance acceptance. Never infer these from local fixture success.

Nothing in this planning document authorises executing a tier. The documentation update is complete separately from future product, native extraction, local SQL and connected acceptance.
