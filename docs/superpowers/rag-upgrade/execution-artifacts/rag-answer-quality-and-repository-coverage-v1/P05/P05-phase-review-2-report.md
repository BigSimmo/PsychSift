# P05 phase review 2

## Findings

### 1. P1 — the real worker can miss a protected identity split across three chunks at its 500-row page boundary

The correction makes the worker use the shared normalized matcher and adds a cross-page overlap, but the overlap retains only the final row of the preceding page: `rows.at(-1)?.content.slice(-256)` (`supabase/functions/indexing-v3-agent/index.ts:1795-1818`). The shared matcher can join only the rows supplied to it (`supabase/functions/_shared/public-source-policy.ts:36-44`). Therefore a protected identity spanning more than two nonblank chunks across the page edge is not reconstructed.

An offline synthetic probe using the production matcher reproduced the bypass with rows 499 = `Australian`, 500 = `Medicines`, and 501 = `Handbook`: the first page returned `false`, its carried value was only `Medicines`, the second page returned `false`, while scanning the three rows together returned `true`. The schema requires only nonblank chunk content and imposes no minimum chunk length (`supabase/schema.sql:295-312,471-475`), so this is a valid persisted-row shape rather than an impossible fixture. The focused worker test checks that the helper is called and that a limit exists, but it does not exercise the actual 499/500/501 boundary (`tests/indexing-v3-agent.test.ts:100-113`).

The upstream acquisition scan remains a strong first gate, but Task 2 explicitly requires the protected/link-only policy to be rechecked in the worker. This boundary leaves that independent policy/licence backstop bypassable if protected wording is introduced or transformed into this chunk layout after acquisition.

Expected correction: retain the last 256 characters of the concatenated scan stream, not only the last row, or use an equivalent cursor/overlap buffer; add an exact three-row, two-page regression through the real worker scan owner.

The final migration and cache corrections close eight of the nine phase-review-1 findings, and the recovery contract remains complete. P05 cannot pass while the explicit worker protected-content parity requirement still has the reproducible boundary bypass above.
