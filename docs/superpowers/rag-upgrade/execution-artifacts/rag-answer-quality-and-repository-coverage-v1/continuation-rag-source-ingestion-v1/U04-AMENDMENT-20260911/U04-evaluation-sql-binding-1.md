## Recommended binding

Use section 6A atomic logical-view equality for the fixed readers below, with evaluation-only SQL bodies whose input relations are exactly the admitted side projections. Preserve existing ordinary RPCs and formulas. A wrapper that checks equality and then calls an ordinary RPC does not generally suffice: ordinary bodies select the active generation, inline live metadata, lack exact population filters, or consult global vocabulary. The evaluation-only bodies must substitute the intended relational inputs before each candidate limit and retain each effective formula, branch, ordering and owner/public combination.

Each externally executable fixed reader accepts a closed-schema session binding, validates the complete current origin and sanctioned candidate/control state, and returns one strict envelope containing the actual verified binding, operation identity and result (including explicit successful empty). The guard must execute even when no rows match. A proposed implementation seam is a service-only, empty-search-path STABLE PL/pgSQL wrapper with an unconditional guard read, followed by a fixed read-only query, both under the calling statement snapshot. Guard plus query cannot be separate HTTP calls; source review must reject volatile factual subcalls or optimizer-prunable guards. This is a design seam, not proof that an unimplemented wrapper has the right snapshot semantics.

The complete guard includes every selected document/artifact/control/source input already required by the origin contract, not only rows a query returns. Generation and ownership filters apply before ordering, candidate caps, aggregation, counts and hydration. Exact C selection does not inherit legacy-null eligibility; any legacy baseline is explicit. Source authority is separately revalidated at final acceptance. No database transaction remains open across providers.
