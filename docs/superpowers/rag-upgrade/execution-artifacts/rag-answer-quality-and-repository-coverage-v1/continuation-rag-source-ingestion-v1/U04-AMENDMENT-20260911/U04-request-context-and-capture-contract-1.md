# U04 review correction: request context and manual-alias capture

This appendix closes R1/R2 of amendment RAG review1 and I1 of schema review1. It changes proposal interfaces only, within the already approved seven shared RAG owners. It requires independent correction review before adoption.

## Exact manual population input

Replace the old capture signature everywhere in the governing interpretation with:

`capture_shadow_reindex_origin(p_document_ids uuid[], p_source_policy_version text, p_manual_alias_ids uuid[], p_execution_profile_digest text) returns jsonb`.

The manual list is mandatory, including an explicit empty array. Document and alias IDs must be canonical ascending unique UUIDs, no nulls; reject duplicates/unsorted input rather than silently normalize. The same validated execution profile used by the local preparation controller contains exactly these document/manual populations. Its digest is the existing strict profile-domain raw-envelope digest; bare64 transport spelling does not change its domain/encoding. The local wrapper validates the complete profile envelope and exact lists before calling this one fixed capture RPC. The server validates digest syntax, document authority, actual manual lineage and owner/public scope, exact requested alias cardinality/full rows, and all row/byte ceilings in this one STABLE capture statement. A digest parameter alone is an identity, not proof of profile approval.

The returned strict origin payload binds `executionProfileDigest` and `manualAliasIds` as well as the complete document/manual alias rows. Baseline evaluation receives and validates the full profile against that identity. Enqueue verifies the full canonical profile envelope/digest and both populations against the returned origin before any mutation, then recaptures the same population under the prescribed barriers. Every later guarded read and seal uses these persisted immutable lists and profile identity; no caller may switch M during evaluation. Profile review authority remains the existing explicit admission process, not a newly invented signature/trust mechanism.

Selected aliases with absent/out-of-W document metadata and disabled aliases are captured in full. Missing IDs, generated/unknown manual lineage, disallowed owner/public scope and conflicting profile membership refuse. Existing approved manual-lineage evidence is required; an ID alone or service-role access cannot relabel a generated alias manual. No new unlisted alias or global alias catalogue enters the comparison. Capture never fetches aliases in a second HTTP request.

Focused proof: same W/source policy with M1/M2 has distinct bound origins; disabled outside-W manual alias retained; enabled/content/removal drift detected; duplicate/missing/foreign/generated/unknown-lineage IDs and wrong profile identity rejected; an unlisted alias excluded; one fixed capture operation. Local mocks establish argument/validation behavior, not hosted snapshot proof.

## Evaluation request context before any ordinary resolver

At both actual `searchChunks` and `answerQuestionWithScope`, the internal evaluation-context branch occurs BEFORE calling `resolveRequestRagCacheContext`, creating an admin client, starting an indexing-version promise or resolving site authority. Ordinary calls without evaluation context keep exactly the current resolver and caches. `skipCache:true` alone is not this branch.

The session owner creates a frozen evaluation request identity from the validated context: wave/plan, side G0 or C, exact document and source authority populations, origin/profile/case-set/config digests, fixed clock and fixed existing rollout mode. Reuse the established canonical envelope algorithm with domain `u04-evaluation-request-v1`; use `u04-evaluation:<digest>` as its document-index identity. This is expressly an evaluation identity, never a live activation receipt.

Build the compatible immutable `ResolvedRagContextSnapshot` using the existing PURE `resolveRagContextSnapshot` helper, with sourcePolicyVersion and rolloutVersion from the bound profile; resolvedAt is the profile's exact ISO clock. Site inputs are exactly expectedSiteStaticManifestDigest=null, activePublicSiteRelease=null, publicSiteChangeEpoch=null, pendingPublicSiteChangeCount=0, pendingPublicSiteLogicalIds=[]. Its site partition is thus disabled, not unavailable and not claimed current. Registry/site corpus operations remain excluded by the fixed evaluation dependency set. Use the helper's ordinary deterministic uploaded-local identity for the synthetic document-index identity and explicit australianPublic={indexGeneration:null,releaseDigest:null}; these compatibility slots do not select evaluation rows or authorize public evidence. Actual owner/public/source authority remains the explicit guarded evaluation context, including its exact approved public document population when applicable. No change to the pure helper or site-content owners is needed.

Nested search and answer share this exact snapshot reference. For evaluation calls, absent supplied snapshot/cache context is valid and gets the session-owned snapshot plus a fresh empty request cache context. A supplied snapshot or supplied cacheContext.ragContextSnapshot must be that same session-owned object, not merely claim matching strings; a different/conflicting object latches context_mismatch and fails closed. If cacheContext.indexingVersionAtRequestStart is present, it must be the identical session-owned promise for the synthetic identity; any foreign promise is rejected without awaiting it. The session constructs that resolved promise itself without invoking ordinary indexing-version code. No supplied mutable cache object is reused or modified; construct a fresh session-owned context. The session closes/freeze-copies its dependency/config records and checks its monotonic failure collector at entry and after nested work.

Evaluation never calls `resolveRequestRagContextSnapshot`, `resolveRequestRagCacheContext`, `cacheIndexingVersion`, `collectSiteContentHealthInput`, ordinary cache readers/writers/coalescing, or creates their promises and overwrites them later. The bound dependency closure supplies actual read/provider operations as already specified. Catching an exception in these branches cannot restore ordinary behavior: record an incomplete evaluation and NO_GO. Adversarial/no-query/empty-result early returns still pass the evaluation identity validation and final failure check, although ordinary fast refusals remain unchanged.

Focused proof invokes actual search AND answer with fake closed evaluation dependencies for absent snapshot, correct supplied snapshot, correct supplied cache context, conflicting snapshot, foreign indexing promise and nested search. Trap ordinary admin/site/index-version/cache calls and assert zero, even with skipCache=true or a prefilled snapshot. Positive ordinary no-context fixtures retain their existing resolver calls/results. Static call-graph review complements these behavioral fixtures; mocks alone do not prove hosted/source completeness.
