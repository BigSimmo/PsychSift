## Important I1 — origin capture cannot receive the reviewed manual-alias population

**Evidence:** `U04-integrated-amendment-candidate-1.md:31` freezes `capture_shadow_reindex_origin(p_document_ids uuid[], p_source_policy_version text) returns jsonb`. There is no pre-capture registered-profile relation/lookup in the five private-table contract, and the profile first reaches enqueue in integrated line 31.

**Trigger:** A valid reviewed profile selects a public or owner-scoped manual alias whose metadata.document_id is absent or outside W; this is permitted by the overlay contract. A disabled selected alias must also be retained so a later enabled flip is detected. Two profiles can have identical W and source-policy version but different manual UUID lists. The frozen capture signature receives identical arguments for both and therefore cannot select the different required populations.

**Expected:** The atomic origin contains exactly the reviewed manual overlay, its full lossless rows and its profile/list identity, alongside document-linked aliases. Subsequent equality checks detect removal, edits and enabled changes without importing unlisted/global generated aliases.

**Risk:** A literal implementation must omit these inputs, reject all nonempty overlays, borrow an unbound global read, or invent another capture interface. Omission makes the claimed complete input snapshot incomplete; blanket refusal fails the expressly supported nonempty-overlay interface. Independently fetching the aliases breaks the selected single-capture contract.

**Smallest correction:** Amend the capture RPC and matching strict TS/result contracts to accept the reviewed profile or a narrow typed manual-alias UUID list plus its already validated profile binding. Validate canonical unique IDs, admitted scope/manual lineage, exact returned population and complete row bytes; bind the list/profile identity into the returned origin envelope. Keep one fixed STABLE statement and the existing bounded document selector. Do not add a generic selector, session GUC, global alias catalogue, or a new policy mechanism. Alternatively explicitly narrow this format to an empty overlay, but that changes the current supported scope and must be stated rather than inferred.

**Smallest later proof:** Same W/policy with profiles M1 and M2 produces distinct correctly bound origins; a selected disabled/out-of-W manual alias is retained; wrong lineage/scope, missing/duplicate UUID, changed enabled/content/removal fail as specified; unlisted aliases do not enter. This is an interface regression to author locally; actual single-snapshot execution remains separately gated.
