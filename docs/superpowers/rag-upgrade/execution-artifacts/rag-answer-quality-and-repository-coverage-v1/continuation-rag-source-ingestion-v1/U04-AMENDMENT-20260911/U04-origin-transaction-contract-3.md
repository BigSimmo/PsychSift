## 4. Transaction transport and cancellation: precise state machine, unresolved driver

Keep the closed operation map and lazy construction from contract 2. A connection may execute only the fixed parameterized operations; caller-supplied SQL/function/table names and transaction callbacks remain forbidden. The intended sequence is acquire -> begin -> set local bounds/role -> fixed operation -> commit -> confirmed terminal cleanup. Read operations and mutations have distinct explicit transaction modes. No provider, model, Storage fetch or native extraction occurs while a SQL transaction is held.

Use one dedicated connection per admitted operation unless an installed/reviewed client gives a demonstrably safe pool lifecycle. A one-connection pool adds little value to this initial bounded administrative path and creates reuse risk after cancellation. Reuse the rest of the existing Supabase application architecture; never replace createAdminClient globally. `src/lib/supabase/admin.ts:12–28` is an HTTP-client singleton, not a SQL transaction client, and cannot establish BEGIN/COMMIT around multiple RPCs.

The concrete outcomes must be discriminated:

1. **not_dispatched**: validation/permit/acquisition failure before any operation statement. No mutation claimed.
2. **rolled_back**: server confirmed abort/ROLLBACK and connection cleanup completed. No accepted result/receipt; serialization/deadlock/timeouts may be reported by fixed typed codes. A client timeout by itself is not this state.
3. **committed**: successful COMMIT acknowledgement, complete validated result/receipt, cleanup completed. Only this can be fresh mutation success.
4. **outcome_unknown**: cancellation, broken transport, deadline or response loss after operation dispatch where commit/rollback is not confirmed. Poison/discard the connection, preserve C/job/operation identity, forbid same-C reclaim or cleanup, and require later separately admitted exact receipt readback. Never turn a successful-looking function row received before COMMIT into success.

Cancellation stops new dispatch immediately. Race-safe settlement must handle abort before acquire, between begin/dispatch, during statement, during commit, and after commit acknowledgement. Do not dispatch ROLLBACK concurrently through a client that still has an uncompleted query. Do not release a connection back to reuse merely because Promise.race returned. A socket close is not affirmative server rollback evidence. Fixed server statement/lock/idle bounds limit abandoned work but are not evidence it has ended at the client deadline.

Keep proposed 5s acquisition / 2s lock / 15s statement / 5s idle / 20s operation budgets as **provisional design limits** subject to complete bounded payload proof; exceeding a bound refuses, never truncates source evidence. A transaction spanning several statements needs a total monotonic deadline, not a new 20s allowance per statement. No generic automatic mutation retry. Any idempotent read retry must preserve the exact expected view and remain within its permit/deadline.

**Driver gate remains unresolved:** package.json/package-lock contain neither pg nor postgres, and neither direct installed package exists. This preparation is local-only and cannot substantiate a current compatible version or its public cancellation/destruction API. Do not invent `query({signal})`, reach into private sockets, or install latest blindly. Before dispatch of the transport owner, root must select an exact package/type version from trustworthy version-matched documentation/source, bind its Node >=24.15.0 <25 compatibility, supported connection termination behavior, parser precision controls, TLS profile and lockfile delta, then review the narrow dependency change. If that evidence is unavailable, this transport portion is not dispatch-ready; mock interface tests alone do not close it.

Proposed environment owner, if direct SQL remains selected: optional `U04_SHADOW_DATABASE_URL`, read only in the lazy command/transaction helper after permit validation; never NEXT_PUBLIC, never a fallback to application URLs or raw environment dumps. The new role/connection identity, certificate verification and exact target profile need separately authorized operator setup. The local supabase/config.toml contains only function settings and does not establish a PostgreSQL server version or connection profile. Target remains Clinical KB Database / sjrfecxgysukkwxsowpy; an RPC returning that string is not independent project verification. No connection secret was read here.

## 4A. Preferred smaller alternative: existing PostgREST, complete short barriers

After the controller's explicit request to assess the existing transport, choose this bounded option for independent review **instead of adding pg, @types/pg, a new SQL connection secret, or the direct transaction helper**. It is feasible as a source design because all mutation effects can live in one fixed RPC transaction. It knowingly trades short global write contention for avoiding a new transport and an unproven mixed-isolation predicate protocol. The impact and server timeout assumptions below still require review; this choice is not runtime acceptance.

**Capture:** implement the fixed capture RPC as one STABLE SQL statement composing only STABLE fixed read helpers. The whole returned origin and measurement view therefore belongs to that statement snapshot. It performs no locking authority call and no mutation, and does not claim that the view remains current after return. All arrays and aggregates use the same explicit population/family projections. The read-only helper from section 2 remains appropriate. A chained series of HTTP requests is not this single capture operation.

**Mutation:** use one VOLATILE fixed RPC at READ COMMITTED. Its first actions validate scalar/envelope shape and acquire a hard-coded relation barrier set in `SHARE ROW EXCLUSIVE MODE NOWAIT`, before source/row locking, factual scans, or any effect. Refuse any other effective isolation unless its semantics are separately proved. Then acquire/revalidate source/document authority, lock actual rows as required by U03, capture fresh full facts after all barriers, compare the expected origin/control state, perform the one allowed mutation, validate its after-image/checkpoint, and return only after transaction completion. No caller chooses relation names, lock mode, lock order or ignored fields. No same-wave automatic retry on contention.

The proposed fixed barrier set, lexicographically ordered and fully qualified, covers documents; pages/chunks/images/table_facts/embedding_fields/index_units/sections/memory_cards/summaries/labels/index_quality; ingestion_jobs/indexing_v3_agent_jobs/ingestion_job_stages/import_batches; rag_aliases; public_source_versions/public_source_activation_events/public_source_serving_authority/document_publication_approvals; and every new U04 wave/member/projection/inventory/baseline table. Additional source/review tables may enter only if the final exact query closure reads them. A parity check binds every factual read/write relation to this allowlist. Keep unrelated query logs/cache tables outside unless their content becomes an actual immutable evaluation input.

The purpose of the complete relation barrier is to block INSERT/UPDATE/DELETE from ordinary READ COMMITTED writers as well as cooperating RPC writers. It closes metadata aliases, inconsistent cross-document stages, child inserts and batch-sibling changes without relying on an FK that does not exist. Taking it before the factual read and using a fresh READ COMMITTED statement snapshot addresses the stale-SERIALIZABLE-snapshot schedule in section 5. It is deliberately stronger and more disruptive than the two-table SHARE suggestion; the two approaches must not be mixed and described as equivalent.

This blocks **all writes to those tables**, not just the selected population, for the duration of the short RPC. It serializes U04 mutations globally and can make ordinary ingestion/publication/manual edits wait. Bound waves and payloads, fail on excess rather than truncate, and use it only for these guarded shadow operations. No provider/model/object/native operation can happen inside the barrier. If actual lease heartbeat/stage frequency or bound payload latency makes this unacceptable, reject the design rather than silently omit tables; that would require a separate complete cooperating-writer design.

NOWAIT makes relation contention a refusal before effects; it is not a bypass or permission to steal locks. Existing transactions may hold compatible ROW SHARE/row/advisory locks and subsequently request a blocked write lock, so relation barriers alone do not prove absence of deadlock. Use the existing try-authority helper where appropriate, closed NOWAIT row-lock queries for U04-owned rows, and finite lock timeout/typed rollback for the remaining existing helper acquisition. No partial writes precede full admission. Explicitly test the cycle where a normal U03 writer already holds a source/document lock and U04 acquires a compatible relation barrier before that writer attempts DML. The expected outcome is bounded refusal/rollback, never a hung lease or successful partial seal.

**Timeout caveat:** a `SET LOCAL statement_timeout` executed inside a running RPC is not accepted here as proof that the already-running top-level statement has an effective absolute deadline. The actual PostgREST/role request timeout must be configured before dispatch, verified later under connected authorization, and bound in the operational profile. The function may enforce explicit clock budgets between bounded operations and set lock_timeout before blocking lock statements, but cannot claim those checks interrupt every long-running SQL expression. This is a remaining connected-admission prerequisite, and the global barrier makes it materially important. No production timeout/role setting is changed now.

**HTTP adapter:** use the existing installed Supabase/PostgREST runtime, lazy after permit validation, with explicit POST fixed RPCs and `.abortSignal(signal)`. Observed local postgrest-js and supabase-js versions are both 2.112.2. `PostgrestTransformBuilder.ts:642–644` stores the signal; `PostgrestBuilder.ts:336–342` supplies it to fetch. The installed retry code retries only GET/HEAD/OPTIONS (`PostgrestBuilder.ts:42–65,349–367`); POST RPC mutation requests are not retried on network failures or status retry rules. Preserve this with a focused contract/mock assertion, and do not introduce a wrapper that retries POST. No globally patched client is needed.

An aborted fetch does not prove database cancellation or rollback. Preserve the four outcome classes from section 4, with HTTP success plus a complete validated committed RPC receipt as success. A network failure/abort after dispatch is outcome_unknown; later exact receipt readback is the only reconciliation, and no cleanup/reclaim follows automatically. PostgREST controls commit and response delivery; no client-side BEGIN/COMMIT queue or connection-pool cleanup is invented. Existing U03 uncertainty rules remain intact.

This preferred alternative removes the pg dependency/version/secret blocker. Remaining design admission is the complete relation/column/query closure and independent review of contention/timeout semantics. Connected evidence must prove actual RPC transaction rollback, effective pre-dispatch timeout, role/grants and the enumerated lock schedules. If root adopts this alternative, update contract 2's blanket SERIALIZABLE checks and direct-connection allowlist explicitly; do not leave two competing transports in the implementer brief.

## 5. Concrete FK/alias/stage coverage and remaining lock blocker

Current schema establishes ordinary document FKs for pages, chunks, images, summaries, labels, sections, cards, table facts, embedding fields, index units, quality, Node jobs, Edge jobs, and stages. Node batch_id and documents.import_batch_id reference import_batches. The inspected definitions are not declared DEFERRABLE. Artifact publication triggers are separately deferrable/initially-immediate; they must stay effective, and cannot be confused with FKs or disabled for U04.

Existing row locks must cover full selected rows, not just generation IDs. Document FOR UPDATE can block a **new** child reference to that document while the parent lock is held. It does not substitute for locks on updates to an already-referenced child's content, nor for query membership without a real FK. Stage.job_id has deliberately no FK. Arrays such as summary source_chunk_ids and card source_image_ids likewise do not acquire source-row locks merely by containing an ID.

The narrow correction to contract 2's proposed predicate barriers is: explicit SHARE locks on BOTH `rag_aliases` and `ingestion_job_stages` at enqueue/seal full-state boundaries, before reading those complete predicates, held only to transaction end. Alias document linkage is metadata-only; the stages OR predicate can include a selected job under an unselected document. These are disclosed short global write pauses on these two tables. Do not add a stage FK to one queue table: job_id intentionally spans Node and Edge. No source-only claim that the two SHARE locks alone close all snapshot schedules is permitted.

Stable intended ordering remains source keys/events/versions -> selected documents -> Node then Edge rows -> fixed artifact/control families -> original batches and sibling closure, with exact sorting within each set. Alias/stage lock placement must be frozen relative to actual U03 writer order and batch-sibling locks. Any deadlock/lock timeout aborts without automatic mutation retry. Existing standard completion takes document/queue before import batch (`U03:666–690`); alias commit takes source/document via Fence then artifact/alias writes (`U03:900–932`). A new batch-first order would therefore be a substantive change, not an innocent optimization.

**Unclosed schedule:** SERIALIZABLE's snapshot can precede acquisition of row/table barriers. A concurrent ordinary READ COMMITTED writer may commit a new predicate member before the barrier is acquired without changing the locked parent row. A later scan can then still use the earlier serializable snapshot. A lone predicate conflict is not a promise that PostgreSQL will abort; do not claim the insert must always raise a serialization error. Likewise, taking a stage table lock only after selecting the snapshot cannot retroactively make that snapshot latest. This matters because the current contract demands exact foreign-state equality at mutation boundaries, not merely a historical consistent view.

Root must freeze one proven strategy before implementation: a complete cooperating-writer/barrier protocol whose acquisition happens before the relevant snapshot, or a short fully protected current-state comparison design with documented isolation semantics. Broad table locks over all document/artifact/queue writers are a possible conservative prototype but would add substantial global contention and are **not selected or authorized by this report**. A permanent refusal for all connected stages is also not a completed implementation. This is an actual design blocker; future SQL tests cannot compensate for leaving the intended schedule unspecified.

Later SQL schedules must cover both interleavings of: pre-snapshot and post-snapshot child insertion, unchanged-parent inserts, same-count content replacement, an inconsistent cross-document stage for a selected job, sibling batch insert/update, alias insert/update, source event replacement, owner/G0 movement, deferred publication trigger failure, deadlock, and response loss. Acceptance requires no partial wave/private checkpoint write and no mistaken receipt success. These are unrun connected proofs, not authorizations to execute them now.

## 6. Evaluator alternative: complete immutable bundles

One valid but potentially larger option is **immutable captured evidence**, rather than mutable G0 reads surrounded by separate hash checks or a transaction held across the whole answer pipeline. The session context binds mode (G0 or C), exact population/owners, immutable origin/baseline bundle digest, candidate immutable receipt digest, expected source authority, closed read-contract version, and session ID. Every fixed evidence dependency reads only that immutable context. The database returns the actual bundle/receipt identity, not an unverified echo of caller expectation.

For G0, read the frozen complete baseline bundle. For C, read that same frozen baseline context plus the complete immutable sealed candidate projection/inventory/receipts. Candidate mutable/incomplete states cannot evaluate. Mutable live singleton summaries/labels/quality/document metadata are not a convenient fallback for missing baseline fields. The existing proposed baseline table must retain complete row payloads needed by retrieval, not only hashes. Fixed read operations may project typed rows from that bundle; do not invent a second unbound generic SQL transport or an alternate simplified ranking implementation. If the actual engine cannot consume a full dependency from the bundle through the approved adapter, that is an implementation gap and NO_GO.

Cached aliases, corpus grounding, quality/labels/summaries, adjacent context, images, fields/units/cards, title/related reads and every fallback branch must use this immutable dependency context. Its fingerprint includes every input that can affect retrieval; owner/global aliases and corpus aggregates are either explicitly frozen in scope or excluded by the exact-wave mode. No unbound background overlay is added. A local cache key must include the immutable context and full operation identity; an ordinary production cache is not evidence ownership.

A provider runs after the SQL read finishes, over retained evidence. Any later expansion/hydration reads the same immutable bundle/sealed generation. Live authority reads before/during/finalization may invalidate the attempt; they cannot replace or enrich the evidence view. Before/after hash equality alone misses intermediate/ABA changes, so it is not a claim that the live state stayed unchanged. Original source event identities/sequences and exact immutable receipts remain required. If future acceptance requires detecting every transient non-source live mutation, an explicit monotonic state revision/event owner is needed; that is not implemented by the current preimage or assumed here.

Before accepting a final report, perform the fixed live source/eligibility validation appropriate to its operation authority, separately from evidence identity. Any observed drift/timeout/unsupported dependency/error mismatch latches NO_GO and prevents the ordinary engine's catch/fallback from manufacturing a valid score. Explicit source-only/fallback behavior can still be recorded as a defined metric scenario; it is not silently substituted for a required provider answer. A historical result remains attributable to its immutable view after later changes; it does not prove current activation eligibility or uninterrupted live-state stability.

No provider or cross-worktree transfer is needed to author offline adapter regression tests. These tests must reach the real engine owners approved at HEAD378c9c, cover dependency omission and fallback suppression, and prove ordinary production behavior unchanged when no evaluation context is supplied. This report does not rename approved owners or reopen that scope decision.

## 6A. Preferred narrower evaluator: atomic equality and evidence in each read

The controller's alternative is also sound at the intended **logical-input** level if implemented completely: each fixed read RPC is one STABLE statement/snapshot which both proves the entire required current origin equals the prepared origin and derives its returned evidence from that same snapshot. A preflight RPC followed by a data RPC, or data followed by a later hash RPC, does not meet this contract. Guard evaluation must be unavoidable even for empty results; do not let optimizer pruning or a zero-row join skip it. Bind the equality verdict and actual operation/evidence result in one strict returned envelope, and reject an absent guard result. All nested callees used for factual reads must retain that snapshot and be read-only; a STABLE label on the outer function is insufficient if an inner volatile helper changes semantics.

For G0, equality covers all original evidence/ranking inputs. For C, equality covers the original baseline plus the immutable sealed candidate state and receipt; the expected sanctioned control state comes from the private exact checkpoint/receipt. Subtract only the server-recorded own additions and validate their exact identities/after-images. Never ignore all queue changes or all rows labelled C. Repeated dependency calls can have different physical snapshots but, when each proves complete input equality, consume the same logical corpus/projection view. Any refused/unsupported/partial read permanently latches NO_GO through tolerant catches and fallbacks.

This does **not** claim the live database stayed unchanged between calls. A live ABA change between calls is harmless to logical evidence identity only when each actual read atomically proves the complete original view and returns no intervening content. If the requirement is to detect any intermediate historical change even when restored before a read, this approach does not prove it and needs a separate revision/event mechanism. Source event sequence/identity remains included, so a governance event cannot be silently treated as an equivalent old event. Source eligibility still requires explicit final validation; the evaluation report remains a statement about its bound inputs, not activation authority.

The closure must include manual/generated metadata, labels/summaries/quality, aliases, title/related/adjacent/image/field/unit/card reads, corpus statistics and caches described in the approved owner extension. Counts alone do not close it. The strict exact-wave mode avoids implicitly taking background/global ranking inputs; any such input actually used must enter the equality contract. No caller-provided generation filter or skipCache flag alone is enough.

**An additional actual ranking input is time.** The effective hybrid formula uses `doc_updated_at > now() - interval '90 days'` (`schema.sql:6702`). Equal row hashes across calls do not freeze that boundary.
