### ING-U03-1 — Shared Node persistence transport failures do not cancel the owning attempt

**Confirmed source defect; P1 / Important.** Owners: `src/lib/document-enrichment.ts:873-889`, `src/lib/deep-memory.ts:614-620`, and `worker/main.ts:1732-1741`.

The summary adapter calls `args.supabase.rpc` directly and converts its error to an ordinary `Error` at line 885. Deep memory does the same in its private mutation closure at line 617. Neither adapter has the owning `IngestionAttempt`, and neither cancels its signal on a transport error. By comparison, the new actual worker transport in `worker/behavior.ts:94-103` cancels on any transport failure, but these real persistence callers do not use it.

Trigger: inline enrichment is enabled and `persist_ingestion_summary_projection`, a deep-memory staging call, or its commit returns a missing-RPC/permission/connection error, including an ambiguous lost response. The optional-enrichment catch checks the still-live attempt, sees an ordinary error, marks enrichment failed and continues. With shadow mode enabled it can subsequently start native shadow extraction (`worker/main.ts:1754-1791`); it also reaches the final document patch and terminal call (`1842-1871`). A deep-memory pre-commit error can additionally issue cleanup through the still-live private closure. This does not demonstrate a stale SQL write bypass: later SQL calls still have fences. It does demonstrate that a required hard failure is downgraded into optional continuation, including more native work and publication after an uncertain persistence outcome.

Violated requirements: U03 contract line 64 requires missing RPC, permission and database failures to be hard failures; line 135 requires one monotonic attempt state and stops subsequent provider/native/Storage calls after missing RPC. The current adapter-specific tests prove rejection and no direct fallback, but their rejection is not proof that the outer worker stopped. The generic transport matrix names summary/deep-memory operations without exercising these different actual adapter transports.

Smallest correction/proof: route both shared adapters' mutations through the same attempt-aware transport, or supply a narrow cancellation/error boundary that distinguishes persistence failures from an ordinary optional provider failure. Preserve acknowledged, fenced pre-commit cleanup semantics and the no-cleanup-after-commit-invocation rule. Add an import-safe actual worker orchestration regression for summary transport failure and deep-memory commit lost response: after rejection the owning attempt must be stopped, and no shadow/native call, quality/document patch, stage/terminal/failure mutation or later provider call may run. Keep an ordinary optional model failure case that still degrades as allowed. No such check was executed by this reviewer.

### ING-U03-2 — An overlapping G0 heartbeat can cancel a successful G1 handoff

**Confirmed source race; P2 / Important.** Owners: `worker/main.ts:1536-1541`, `worker/main.ts:1656-1665`, `worker/behavior.ts:94-103`, and `supabase/functions/_shared/ingestion-attempt.ts:77-116`. SQL counterparts: new migration lines 149-155, 354-370 and 631-643.

The interval launches an unawaited heartbeat independently of other mutations. `runIngestionMutation` captures the current Fence when dispatching each RPC; there is no per-attempt serialization or drain around core commit. Core commit advances the durable expected generation and document pointer to G1 and returns the G1 Fence. A heartbeat that captured G0 during that operation will correctly fail the SQL generation check once it acquires the document lock after the commit. Its response then permanently cancels the same still-current job/token locally.

Concrete schedule: (1) start the core commit with G0; (2) fire the timer before the response arrives, submitting a heartbeat with G0; (3) commit succeeds and its response performs the local G1 handoff; (4) the queued heartbeat observes durable G1, returns `lease_lost`, and aborts the local attempt. The same failure is possible if the stale heartbeat response arrives first: cancellation prevents accepting the successful commit response. No reclaim or policy change is required. In-flight progress heartbeat calls also need consideration; clearing an interval does not drain a request already started.

Result: a valid core generation remains committed, but enrichment/terminal work is abandoned and the job remains processing until expiry. Repeated reclaim consumes attempts and can leave a last-attempt processing row without a remaining claim budget. This is a liveness defect, not evidence that the SQL fence should accept stale G0.

Violated requirement: the durable G0-to-G1 handoff and continued G1-only writes in contract line 60 must work with the newly introduced heartbeat owner; lines 189/195 require handoff and stale-call behavior proof. Existing tests check a sequential successful handoff and independently stale transports, not this interleaving.

Smallest correction/proof: serialize the affected attempt mutation dispatches so the Fence is captured only when each request is actually admitted, or explicitly quiesce/drain all renewal/progress requests across the handoff and resume using the returned Fence. Do not weaken server generation predicates or simply ignore every heartbeat refusal. A deferred-promise test using the actual transport and timer/handoff owner can prove both response orders without SQL or providers: a current successful handoff stays usable, while a truly replaced token still cancels. The schedule above is derived from source; it was not executed here.

### ING-U03-3 — Caption and model-index requests omit the available provider cancellation signal

**Confirmed cancellation-closure omission; P2 / Important.** Changed owners: `worker/main.ts:896-908` and `src/lib/deep-memory.ts:626-647`. Required transitive seams inspected: `src/lib/openai.ts:1102-1113,1143-1161`, `src/lib/model-index-extraction.ts:364-380`, and `src/lib/openai.ts:145-155,460-535`.

The attempt is checked before/after image captioning, and deep memory checks the supplied signal around model-profile generation. However, neither `classifyAndCaptionImageFromBase64` nor `generateModelIndexProfile` accepts or forwards that signal. Both ultimately call `generateStructuredTextResult`; its options and SDK request options already support `AbortSignal` and configured retries.

Trigger: a caption/model-index request receives a retryable failure or is waiting in SDK retry backoff when a renewal failure cancels the attempt. The request has no knowledge of that cancellation and may send the next configured attempt; only the outer post-call check stops later publication. This is additional provider work after cancellation, not merely completion of bytes already sent. Signal propagation is already present for the summary and embedding paths and for Edge embedding requests, so the closure is inconsistent.

Violated requirement: contract line 135 requires propagation where supported and bounds subsequent provider work. The existing deep-memory cancellation test injects cancellation and throws from a mocked `generateModelIndexProfile`; it does not prove the real wrapper forwards a signal or interrupts retries.

Smallest correction/proof: explicitly admit the two narrow wrapper parameter changes if their currently unlisted owners need a scope amendment, then forward the same optional signal to the existing text-generation request options and pass it from both ingestion callers. Preserve ordinary callers' defaults. Use provider-free deferred request/retry mocks at the actual wrappers: cancel the attempt while the first request/backoff is pending, assert the same signal reaches the lower provider boundary and no second request starts, with no result publication. No live-provider check is required to expose the source omission.
