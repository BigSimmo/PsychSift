## Important findings

### U03-CG-01 — Persistence transport failures do not cancel the real Node attempt (P1)

**Owners and locations:** `src/lib/document-enrichment.ts:873–887`, `src/lib/deep-memory.ts:614–620`, and their actual orchestration in `worker/main.ts:1732–1740`, `1765–1787`, `1842–1871`.

**Trigger:** An otherwise current inline-enrichment attempt receives a missing-RPC/permission/transport error from `persist_ingestion_summary_projection`, any deep-memory staging RPC, or the deep-memory commit RPC. Other RPCs, such as progress/document state/completion, remain available. A lost response from a committed write is another instance of the same path.

**Confirmed source path:** Both shared persistence owners invoke `supabase.rpc` themselves and convert its `error` to an ordinary `Error`; a rejected RPC promise also escapes as an ordinary error. They receive a Fence and read-only AbortSignal, not the owning `IngestionAttempt`, and neither cancels it for that transport failure. `processJob` cancels/rethrows only an `IngestionAttemptError` or an already-aborted attempt. The ordinary error is therefore handled as optional enrichment failure. Execution can perform the later shadow preparation/native work, write final document metadata, and complete the job. A successful subsequent heartbeat does not fix this because no cancellation was recorded. On some deep-memory staging errors the helper additionally invokes fenced cleanup after the original transport failure.

**Violated requirement:** The execution contract requires one monotonic attempt state and says missing RPC/database/transport failures are hard failures; cancellation must stop subsequent provider/native/Storage work and publication. Ordinary optional model/enrichment degradation is a different condition. The correctly cancelling `runIngestionMutation` seam in `worker/behavior.ts:81–106` does not protect these direct RPC callers.

**Effect:** The worker can report a deferred/completed core lifecycle and continue work after a persistence failure whose outcome or installed contract is unknown. An ambiguous successful deep-memory commit can be followed by metadata saying enrichment failed, with zero section/card counts and null update stamps. SQL fencing still protects a genuinely replaced attempt; that protection does not satisfy the required transport-failure cancellation path.

**Smallest correction and proof:** Route every shared persistence transport failure through the same owning attempt, or propagate a typed fatal persistence error which the real worker cancels before any further work. Preserve ordinary optional-provider failure semantics and the no-cleanup-after-commit rule. Add a provider-free regression through the actual Node orchestration, with inline enrichment enabled, a current claim, one summary/stage/commit transport error, and successful remaining mock RPCs. Assert the owning signal becomes aborted and that no later native/provider/Storage call, document metadata mutation, failure/retry mutation, or terminal completion runs. Include a lost-commit-response variant and an ordinary optional-model-failure positive control. Existing wrapper-only tests do not exercise this bypass: `tests/ingestion-lease-fencing.test.ts:39–115` calls the safe transport seam directly. No new check was run by this reviewer.

### U03-CG-02 — Fallback preserves a structured row that the accepted normalizer rejected (P1)

**Owners and locations:** New migration `supabase/migrations/20260831101000_fence_ingestion_leases_and_repairs.sql:320–324` and mirror `supabase/schema.sql:12062–12066`; actual Edge path `supabase/functions/indexing-v3-agent/index.ts:810–834`, `1675–1686`.

**Trigger:** A stored same-generation payload says `summary_kind = structured` but fails the accepted U02 normalizer, for example because a claim has an invalid source/page/aggregate relationship, or its structured model identity no longer matches the independent expected model/version. Existing generated labels and other current-generation strict-gate artifacts are still present.

**Confirmed source path:** Edge `ensureSummary` attempts the full normalizer and catches rejection into `stored = null`. It creates the required zero-label provisional fallback and invokes the new atomic persistence function. That SQL function checks only the old row's `summary_kind` and `index_generation_id` before returning `ok:true, preserved_structured:true`. It does not establish that the old structured payload is valid under the current source/model authority. It exits before replacing the old summary or deleting its generated labels. Edge ignores the returned persisted summary and returns its locally built fallback. `processJob` then reads the strict gate, whose existing definition counts current-generation artifacts/labels and embeddings rather than revalidating the stored source-anchored payload (`supabase/schema.sql:4359–4516`); if those artifacts are present it can complete the job immediately.

**Violated requirement:** The contract permits preservation of an **already valid** structured payload and requires provisional Edge fallback to remain zero-label and unable to complete structured enrichment. The accepted U02 normalizer's refusal cannot be overridden by two metadata fields. This is structural/source-identity validation, not a request for new semantic entailment logic.

**Effect:** A rejected persisted payload and its generated labels survive the fallback transaction and may receive a completed enrichment lifecycle. The actual database state disagrees with the fallback object used by the producer. This is a new fail-open branch introduced by the preservation guard, not a request to change the inherited strict-gate thresholds.

**Smallest correction and proof:** Preserve a current structured row only with the complete required validity/identity evidence, and make the actual persisted outcome authoritative to the caller. A rejected same-generation row must be replaced atomically by the provisional fallback and zero generated labels, or cause explicit refusal; it must not silently remain completed. Add an actual Edge-summary-path regression using a faithful persistence boundary: (1) malformed same-generation structured payload with existing generated labels and otherwise complete artifacts; (2) valid structured same-generation positive control. In the first case assert stored row/labels and caller result agree, the invalid row cannot remain usable, and strict completion is refused/deferred. In the second preserve the valid payload. Add a configured-model mismatch variant if that identity is used as the rejection trigger. Current summary mocks always replace the row and therefore do not model this SQL early return (`tests/document-enrichment.test.ts:357–384`); current Edge fallback tests construct a gate with zero labels rather than exercising this interaction (`tests/indexing-v3-agent.test.ts:1086–1112`). Separately authorised SQL proof must eventually establish transaction behavior; none was executed here.
